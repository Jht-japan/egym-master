## 2. スター3 確認テストの新設（2555b5c）

- スター2テストと同じ仕組みで、スター3用の AI採点テストを追加（「テスト」タブ）。
- 15問（AI採点12問＋自己確認3問）、5日タイマー・自動保存・問題別フィードバック・80点合格・再受験。
- クラウド保存（`trainer_progress.test`）。認定手順に「確認テスト合格」を組み込み。
- `grade-test` Edge Function に スター3 の採点基準（`s3q1`〜`s3q12`）を追加。

## 3. テスト解放条件を「育成完了後」に変更（8b901c4）

- スター3テストの解放要件を **チェックリスト100% ＋ スター2認定2名 ＋ 顧客2名のB/A（Before/Mid/After）** に変更。
- テストは「自分の勉強」ではなく **育成成果を出したあとの最終ステップ** という位置づけに。

## 4. スター3テスト内容の刷新（9c2d892）

- 内容をビジネス・リーダーシップ領域へ全面刷新（7セクション）：
  リーダーシップ・チーム育成／顧客との関係構築・LTV／**退会率の改善**／**新規獲得の改善**／現状の課題認識・改善提案（感じる問題点・改善点）／ケーススタディー（店舗経営）／自己確認。
- ⚠️ 設問・採点基準は**下書き**。最終的には JHTJapan にて確定すること。

## 5. テスト解放の承認フロー＋レポート共有＋認定要件（4c7be8e）

新テーブル `test_records` を追加し、3つの連動機能を実装（スター2・スター3共通）。

- **テスト解放の承認（Super）**：トレーナーが前提条件達成後、Super管理者へ「テスト解放」を申請 → **Super が承認するまでテストは受験できない**。状態＝none/requested/approved/rejected。
- **テストレポート共有**：提出時に 点数・全設問の回答・AIフィードバック を `test_records` に保存。**担当メンター（スター2/3）・施設・Super が閲覧可能**。super／facility に「テスト」タブ（super=解放の承認/却下＋全レポート、facility=自施設レポート）を追加。
- **認定にテスト合格を必須化**：スター3の `doCertify`・施設の `approveCert` は、**対象スター2がテスト合格（80点以上）していないと認定不可**。（スター1はテスト無しのため対象外）

## 6. test_records の RLS 修正（b41d341）

- テスト中に判明：本プロジェクトは**新規テーブルで RLS が自動有効**になるため、ポリシー無しの `test_records` は**ログイン済みユーザーでも書き込み不可**だった（＝機能が動かない）。
- `create-test-records.sql` に Phase3用の許可ポリシー（`allow_all_test_records`／authenticated）を追加。`tighten-rls.sql` は Phase4 でこれを drop してロール別に厳格化。
