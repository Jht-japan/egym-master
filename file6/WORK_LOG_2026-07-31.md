# 作業ログ 2026-07-31

## テーマ: メンター引き継ぎ（ハンドオフ）機能の実装 & Orphan バグ修正

対象ファイル: `egym_super_account.html`（オーナー画面のみ）
仕様書: `SPEC_メンター引き継ぎ.md`（同フォルダ）

### 背景
- オーナーが Star2/Star3 を削除すると、配下候補者の `mentored_by` が削除済みidを指したまま残り、
  UIに出ず認定ハンドシェイクが壊れる（Orphan バグ）。
- 中断・異動時に育成中候補者を別トレーナーへ引き継ぐ正規フローが無かった。

### オーナー承認の決定（2026-07-31）
1. 削除時は **強制引き継ぎ → 削除**（宙に浮かせない）。
2. 新メンターは **同施設・正しい上位レベル・認定済み**（star1→認定済みstar2 / star2→認定済みstar3）。
3. **Star3 の直接追加を廃止**（昇格ボタン経由のみ）。

### 実装内容
- **loadAllData**: 全存命id集合を作り、各トレーナーに `mentoredByLive` / `orphaned` を付与。
- **追加モーダル**: star3 option を削除＋案内文（昇格のみ）。
- **rHome**: 孤立が1件以上で赤バナー（件数＋施設管理への導線）。
- **施設詳細**: 「⚠ 要メンター割当」カード（孤立=赤/未割当=アンバー）＋各行「メンター割当」。
- **育成ツリー**: 各候補者行に「メンター変更」ボタン追加（自主引き継ぎ）。
- **rModal**: `reassign|fid|menteeId`（割当/変更）と `handoff|fid|tid`（削除前引き継ぎ）の2モーダル追加。
- **delTrainer**: 存命候補者を持つ場合は即削除せず引き継ぎモーダルを起動。
- **新規関数**: `sbReassignMentor`（ガード無し上書き）/ `eligibleMentorsFor` / `reqLevelLabel` /
  `openReassign` / `doReassign` / `openHandoff` / `doHandoffDelete`。
- 既存 `sbAssignMentor`（未割当のみ許可）はそのまま維持。

### 挙動メモ / 注意点
- 適格メンターが施設に1人もいない場合、引き継ぎ不可 → 当該メンターの削除もブロック（案内表示）。
  運用でロックするなら `eligibleMentorsFor` から `status==='certified'` を外して「進行中も許可」に緩和可能。
- 候補者本人の進捗は `trainer_progress`（候補者idキー）に保持されるため、引き継ぎ・削除で消えない。
- RLS: 現状 allow-all なので `trainers.update` は通る。`tighten-rls.sql` 適用後は判断①に従い
  この update 経路（`sbReassignMentor`）も対象に含めること。
