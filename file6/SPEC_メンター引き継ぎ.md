# メンター引き継ぎ（ハンドオフ）機能 — 技術仕様

> 対象ファイル: `file6/egym_super_account.html`（オーナー画面のみ）
> 目的: メンター（Star2/Star3）が育成を継続できなくなった場合に、育成中の候補者（メンティー）を
> 別の適格トレーナーへ安全に引き継ぐ。あわせて「メンター削除で候補者が宙に浮く（orphan）」バグを解消する。
> 決定事項（2026-07-31 オーナー承認）: ①削除時は強制引き継ぎ→削除 ②新メンターは同施設・正しい上位レベルの認定済みトレーナー ③Star3の直接追加は廃止（昇格のみ）

---

## 1. 背景と課題

### データモデル（現状）
- メンター関係は `trainers.mentored_by`（メンティー行に、メンターの trainer id を保持）で表現。
- ルール: **Star2 が Star1 を育成 / Star3 が Star2 を育成**（1メンター対多メンティー可、1メンティーは1メンター）。
- メンティー本人の進捗は `trainer_progress`（メンティーの trainer id をキーに保持）→ **メンター変更・削除でも進捗は消えない。**

### 現状の問題
1. **Orphan バグ（要修正）:** オーナーがメンター（Star2/Star3）を削除すると、その配下メンティーの
   `mentored_by` は削除済み id を指したまま残る。UIのどこにも表示されず、**認定ハンドシェイクが破綻**する
   （誰もそのメンティーを認定できない）。
2. **引き継ぎ手段が無い（要新規）:** メンティーを別メンターへ移すには「解除→再割当」の2手動ステップが必要で、
   かつ `sbAssignMentor` は既にメンター有りのメンティーへの割当を拒否する。中断時の正規フローが存在しない。

---

## 2. 用語

| 用語 | 定義 |
|---|---|
| メンター | 育成する側。Star2（Star1を育成）/ Star3（Star2を育成）。 |
| メンティー | 育成される候補者。`mentored_by` に自分のメンターidを持つ。 |
| **未割当 (unassigned)** | `mentored_by = null`。新規追加直後など正常状態。案内のみ。 |
| **孤立 (orphaned)** | `mentored_by` が設定されているが、そのidのトレーナーが存在しない（削除済み）。**異常＝要対応。** |
| 適格メンター | 同施設・正しい上位レベル・`status='certified'` のトレーナー。 |

**適格メンター判定:**
- Star1 メンティー → 同施設の **認定済み Star2**
- Star2 メンティー → 同施設の **認定済み Star3**
- （Star3 はメンティーになり得ない）

> ⚠️ トレードオフ: 「認定済みのみ」を新メンター条件とするため、施設に認定済み上位トレーナーがいない場合は
> 引き継ぎ不可（＝そのメンターの削除も不可）となる。運用でロックする場合は「進行中も許可」へ緩和可能（§7）。

---

## 3. 機能スコープ（3つのフロー）

### フロー A — 自主引き継ぎ（メンター変更）
育成ツリー上の各メンティー行に「メンター変更」操作を追加。中断・異動などで、削除を伴わずに
別の適格メンターへ移譲できる。

### フロー B — 削除時の強制引き継ぎ（Orphan 予防）
`delTrainer` を拡張。削除対象が**存命メンティーを持つ**場合、即削除せず「引き継ぎモーダル」を表示。
全メンティーに新メンターを割り当ててからでないと削除できない。適格メンターがいないメンティーが
1名でもいれば削除をブロックし、理由を提示。

### フロー C — 既存 Orphan の可視化・解消（Orphan 修正）
`loadAllData` で各トレーナーの `orphaned` を算出。
- **ホーム画面:** 孤立が1件以上あれば警告バナー（件数＋施設管理への導線）。
- **施設詳細:** 「⚠ 要メンター割当」カードに、その施設の孤立・未割当メンティーを一覧表示し、
  各行から「メンター割当」できる。

---

## 4. データ算出（loadAllData 拡張）

トレーナー構築時に、全存命 id 集合 `liveIds` を作り、各トレーナーへ次を付与:

```js
mentoredBy    : t.mentored_by,                       // 既存
mentoredByLive: !!t.mentored_by && liveIds.has(t.mentored_by),
orphaned      : !!t.mentored_by && !liveIds.has(t.mentored_by),
```

`mentoring`（配下メンティーidの配列）は既存どおり存命トレーナーのみから構築 → 削除済みメンターの
関係は自然に消える。孤立メンティーは自分の star グループに通常表示され、`orphaned=true` で判別。

## 5. UI 仕様

### 5-1. ホーム警告バナー（フロー C）
- 条件: `allTrainers().some(t => t.orphaned)`。
- 表示: 赤系バナー「メンター未設定の候補者が N名います」＋「施設管理で対応 →」ボタン。

### 5-2. 施設詳細「⚠ 要メンター割当」カード（フロー C）
- 対象: その施設の Star1/Star2 で `orphaned || mentoredBy==null`。
- 各行: 氏名・レベル・状態タグ（孤立=赤 / 未割当=アンバー）＋「メンター割当」ボタン → 再割当モーダル。
- 該当0件なら非表示。

### 5-3. 育成ツリー内「メンター変更」（フロー A）
- 既存の各メンティー行（解除ボタンの隣）に「変更」ボタンを追加 → 再割当モーダル。

### 5-4. 再割当モーダル（フロー A・C 共通）`reassign|fid|menteeId`
- 見出し「メンターを割り当てる / 変更する」＋対象メンティー名・レベル。
- 適格メンター一覧（§2判定、現メンター除外）を選択肢に表示。各行「割り当てる」。
- 適格メンター0件: 「この施設に認定済みの{上位レベル}トレーナーがいません」＋案内。

### 5-5. 引き継ぎモーダル（フロー B）`handoff|tid`
- 見出し「{名前}さんを削除する前に、育成中の候補者を引き継ぎます」。
- メンティーごとに1行 + 新メンター選択（select）。適格0件の行は赤警告・選択不可。
- フッター:
  - 「キャンセル」
  - 「全員を引き継いで削除」= 全行に有効な選択があるときのみ活性。押下で
    各メンティーを `sbReassignMentor` → 最後に `sbDeleteTrainer` → リロード。
- 適格0件の行が残る場合は削除不可（ボタン非活性＋理由文）。

## 6. データ層関数

```js
// 既存 sbAssignMentor は「未割当のみ許可」を維持（フロー Cの未割当ケース）。
// 孤立ケース・変更・引き継ぎでは下記を使う（ガード無しで上書き）。
async function sbReassignMentor(menteeId, newMentorId){
  var { error } = await _sb.from('trainers')
    .update({ mentored_by: newMentorId })
    .eq('id', menteeId);
  if(error) throw error;
}
```

- **RLS 注意:** 現状 allow-all のため `trainers.update` は通る。`tighten-rls.sql` 適用後は
  判断①（Edge Function 経由 or ポリシー許可）に従い、この update 経路も対象に含める。

## 7. エッジケースと方針

| ケース | 挙動 |
|---|---|
| 適格メンターが1人もいない施設でメンター削除 | フローBで削除ブロック。「先に上位トレーナーを認定してください」。 |
| メンティーが既に認定済み | 引き継ぎ対象に含めるが、新メンターは監視のみ（認定は済んでいる）。UIで「認定済」表示。 |
| 保護アカウント（PROTECTED_EMAILS） | 従来どおり削除スキップ。引き継ぎ判定より前にガード。 |
| 新メンター条件を「進行中も許可」に緩めたい | §2の判定から `status==='certified'` を外すだけ（1行）。運用で決定。 |
| Star3 の直接追加 | 追加ドロップダウンから star3 を削除（決定③）。Star3 は昇格ボタン経由のみ。 |

## 9. テスト観点（E2E）

1. Star2 に Star1 を2名割当 → その Star2 を削除 → 引き継ぎモーダルで別の認定済み Star2 へ2名再割当 → 削除成功、両名の `mentored_by` 更新・進捗保持。
2. 認定済み Star2 が施設に他にいない状態で当該 Star2 を削除 → ブロック＋案内表示。
3. 過去に発生済みの孤立データ → ホームバナー＆施設カードに表示 → 割当で解消。
4. 育成ツリーの「変更」→ 別メンターへ移譲 → ツリー再描画で反映。
5. 追加モーダルに star3 が出ない。昇格ボタンからのみ star3 到達。
